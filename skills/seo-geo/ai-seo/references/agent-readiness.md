# Public content access and parsing

Assess the actual consumer and task before adding machine interfaces. Check public HTTP status, substantive rendered/initial content, semantic navigation, labels, canonical URLs, sitemap discovery and recoverable errors. Some consumers execute JavaScript and others do not; observe the relevant path rather than assuming universal limitations.

Preserve authentication, WAF protections and approved crawler policy. Never make private data public for discoverability. External checker scores are optional diagnostics and not evidence that all agents can act reliably; no installer, third-party upload or API is required.

If a real integration needs Markdown or another representation, specify content parity, canonical identity, freshness, access controls and cache Vary behavior. Test that a public export contains no draft, internal or personal data. Do not add llms.txt, full-site dumps or callable tools solely for speculative ranking benefit.

For agent actions such as bookings or purchases, require the application's authorization, validation, idempotency and confirmation boundaries. Discoverability does not authorize a transaction. Use api-designer and security-code-review only when that implementation is in scope.
