# Journey and usability checks

Use this only when the selected UI piece participates in a longer user task.

1. Write the user's goal and entry point in one sentence. Map the shortest successful path through the prototype, including the exit or completion state.
2. Add one realistic detour or failure state that changes the user's choice: validation error, empty result, permission denial, stale data, or recoverable network failure. Make the recovery action real in each relevant variant.
3. Define two or three tasks a participant can attempt without coaching. Observe whether they find the next action, understand feedback, and recover from the detour. Record behavior and quotes separately from interpretation.
4. Compare variants on the same content, data, tasks, and device size. Keep their distinct interaction models; do not normalize away the difference under test.
5. Report what was observed, what remains hypothetical, and which variant best supports the task. The user still chooses whether to promote one.
